# Three-minute technical demo script

**Recording status:** local Anvil/TestUSD rehearsal only until a public Monad canary is actually deployed and independently verified. Keep the opening disclosure on screen: “Local Anvil/TestUSD: no real funds, no public transaction.” Replace that label only after the corresponding evidence exists.

## 0:00–0:20 — frame the problem and the boundary

“Agents can call services, but a service purchase still needs a narrow, inspectable budget. Agentonomy Commerce keeps identity, policy, reservation, and audit in Core, then adds a user-signed ERC-20 ceiling for one purchase rail. This recording uses local Anvil and a test token. It is not a Monad transaction or a claim of production readiness.”

Show the repository branch and the status line from `docs/monad/source-baseline.md`. Do not show private keys or raw runtime databases.

## 0:20–0:55 — show the path

Display the flow:

```text
Agent → clink_node MCP / Marketplace → Core
     → Budget Executor → two-RPC Watcher → fixed HTTP merchant
```

“Core first verifies the existing EIP-191 Spending Grant, the merchant and resource scope, policy/risk, and a budget reservation. The user then signs an EIP-712 `SpendGrant` that fixes the token, payee, limits, validity window, scope, and execution signer. Core signs a separate per-purchase execution permit. The contract is ordinary ERC-20 code: no EIP-7702 dependency, no proxy, no arbitrary call surface.”

Show `docs/monad/design.md` and the two exact type strings. Point out that `grantHash` is the full EIP-712 digest and all wire amounts are canonical unsigned decimal strings.

## 0:55–1:25 — create a bounded purchase

Run the local test command or the checked-in local composition. Show the fixed CSV offering, the frozen quote, and the budget snapshot. The sample price is 0.30 TestUSD units represented as 300000 six-decimal base units; it is a local/testnet parameter.

“The agent cannot select an owner, grant, signer, token, payee, or arbitrary merchant URL. Core binds the chain grant one-to-one to the existing spending mandate. The relayer only supplies gas. Test keys are generated by the local process and are not stored in the repository.”

Do not imply that a local generated key is a user wallet or that TestUSD is official USDC.

## 1:25–1:55 — show on-chain enforcement and independent verification

Show the contract test or local receipt with the `PaymentExecuted` and ERC-20 `Transfer` events. Highlight that the contract checks:

- owner and execution signatures in the exact EIP-712 domain;
- fixed token and payee, validity, per-payment and total caps;
- owner-scoped revocation, owner/purchase replay protection, and grant-body pinning;
- exact 32-byte `transferFrom` success and exact owner/payee balance deltas.

Then show the watcher projection. “A receipt alone is not success. In both local and public modes, each RPC observation must carry the full signed calldata, transaction and receipt block identity, a canonical block matching the receipt, exactly one payment event, exactly one token transfer, and an explicit finality canonical boundary. The two observations must agree on that boundary. Public Monad mode requires `monad_verified`; local mode is labelled `local` and `local_anvil`.”

## 1:55–2:25 — replay and recovery

Restart the local composition and execute the same preview again. Show that the purchase ID, settlement identity, and delivered result remain the same, while the budget is not charged again.

“If a worker exits after broadcast, the journal resumes the same attempt. A missing receipt or RPC disagreement stays unknown and retains the reservation. If payment is verified but delivery fails, recovery retries delivery only. It never creates a replacement payment to hide an uncertain outcome.”

If the environment cannot start Anvil, show the test failure as an environment limitation rather than substituting simulated success.

## 2:25–2:45 — demonstrate negative cases

Show selected protocol, contract, and watcher tests for a wrong domain/chain, changed amount or payee, expired grant, revoked grant, repeated purchase, malformed token return, duplicate event, and RPC disagreement. “These checks are implemented locally. Their existence is not a third-party security audit.”

## 2:45–3:00 — close with honest status

“Monad testnet chain ID 10143 and the read-only finality boundary have been checked. The public token, executor, payee, transaction, service URL, and external developer feedback are still pending. Once a user-approved canary supplies those facts, the same evidence format will show the real transaction and Verified boundary. Until then, this is a reproducible local implementation and an explicit deployment plan.”

End on the pending-evidence table in [`README.md`](README.md). Never replace it with a fabricated address, transaction hash, customer logo, or adoption number.
