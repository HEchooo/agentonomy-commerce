# ERC-8004 Commerce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.

**Goal:** Identify the CSV service through ERC-8004, check its receiving wallet before a new purchase, let an authenticated buyer publish feedback about a verified delivered order, and describe the complete architecture in README.

**Architecture:** Keep copied Core/Node/Marketplace as the financial authority. An optional operator-pinned registry adapter at the hosted composition adds independently verified service identity and buyer-wallet feedback; it cannot choose a budget, change a merchant, sign, or broadcast. Public registration and feedback documents contain public metadata only.

**Tech Stack:** Python 3.12, eth-abi/eth-utils, existing read-only RpcClient and two-RPC finality verifier, SQLite, FastAPI, EIP-1193 browser wallet, pytest and local Anvil.

**Status (2026-10-08, Asia/Shanghai):** The implementation and current observed
local gates are documented below. The Monad pytest portion has 549 passed and the
canonical Core budget gate has 21 passed; the root agent is adding cross-tab UI
cases and rerunning `test-monad`, so this plan deliberately leaves the final Monad
aggregate unnumbered. Other observed gates are contracts 64, Commerce 25, Review
76, submission 6, canonical Core OPC 108 and Node OPC/MCP 121, all passed.

## Global Constraints

- Baseline commit `9ecf6b0ce42cda99269e9699483e5d8a0d65db4f`; standalone repository only. No sibling imports, Clink changes, AWS credentials, IAM or live broadcast.
- Pin ERC-8004 reference interfaces to official contracts commit `b9e466c250744a7e06b13dff9d3c2844ed64f825`; Identity/Reputation implementation versions 2.0.0. The specification remains Draft.
- Monad testnet chain10143; local fixtures explicitly chain31337. No mainnet or chain fallback. Reuse the configured two independent RPCs and `verified_boundary`.
- Registry config must pin proxy runtime hashes AND EIP-1967 implementation address/runtime hashes on Monad. Local test fixtures may explicitly use nonproxy registries. Recheck common verified block/hash and current metadata, not just an old address list.
- Expected service owner, receiving wallet and agentURI are operator pins. Registry receiving wallet must equal the existing network payee; transfer, URI/code/implementation/network disagreement blocks new purchases. No arbitrary remote URI fetch or visitor-selected registry/Agent/payee.
- ERC-8004 does not grant spending permission. Core login, signed grant, allowance, policy/risk, reservation, execution recheck and audit remain mandatory.
- A previously paid order must remain recoverable when service identity changes. A recovery that could initiate payment needs the same identity check as execute.
- Feedback is optional and buyer-signed through the connected wallet, with zero native value. Never send through KMS, grant a token allowance, generate a user key or automatically send on refresh.
- Feedback may only reference that buyer's persisted delivered order, canonical Core two-RPC payment proof and persisted SHA-256 output_hash. Do not publish CSV, report contents, input_hash, grant/signature/session/Agent credential, internal tenant ID or internal order ID.
- Freeze a canonical feedback document and calldata per authenticated wallet/tenant and order in a feedback record store separate from ordinary purchase references. Persist the original submitted transaction hash before RPC verification; pending/unknown or a competing hash never triggers a replacement submission. Only publish its JSON after verifying the exact buyer/from, registry/to, calldata, zero value, receipt/finality and NewFeedback event through both RPCs. Keep revoked historical feedback distinguishable.
- The browser flow is explicitly prepare -> inspect disclosure -> send. Same-origin tabs in the same browser profile take an exclusive `navigator.locks` send lock and reread the durable per-wallet/order record before sending. Unknown markers survive refresh/crash; cancellation `4001` clears one only inside the originating lock. Unsupported Web Locks or localStorage fail closed for optional feedback sending. This coordinates only the same origin/profile, so other devices, profiles or cleared storage can hide a pre-hash unknown attempt; preserve browser metadata and check the original wallet transaction during recovery. Backend original-candidate enforcement begins only after a transaction hash is submitted.
- With no ERC config the previous composition remains explicitly registry-unconfigured. The packaged new public deployment must explicitly supply the ERC config; incomplete config fails closed. Do not advertise an internal MCP endpoint as publicly reachable.

## Task 1: Registry adapter and ABI boundary

**Files:** `agentonomy_commerce/erc8004.py`, `agentonomy_commerce/budget_network.py` (read-method constant only), `tests/monad/test_erc8004.py`.

**Interfaces:**

- `RegistryConfig.from_dict(value, *, network, origin)` rejects unknown/missing fields. Fields: `identity_registry`, `reputation_registry`, `agent_id` (nonnegative int or None when registration pending), `agent_owner`, `agent_uri`, `identity_code_hash`, `reputation_code_hash`, `identity_implementation`, `identity_implementation_code_hash`, `reputation_implementation`, `reputation_implementation_code_hash`. agent_uri must be `origin + '/agent.json'`. Four implementation fields may all be None only in local_anvil.
- `ERC8004Client(network, config, *, client_factory=RpcClient)` has no signing/broadcast capability.
- `verify_identity()` returns verified identity with `agent_registry`, `agent_id`, `agent_owner`, `agent_wallet`, `agent_uri`, `chain_id`, `block_number`, `block_hash`. agent_wallet must equal network.payee.
- `registration_document()` returns the normative registration-v1 shape with a web endpoint, actual registrations, x402Support=false, supportedTrust=['reputation']; only registered verified identity is active. No public MCP claim.
- `feedback_transaction(*, buyer, score, feedback_uri, feedback_hash)` checks current identity and registry `isAuthorizedOrOwner(buyer, agent_id)` at the same verified boundary. Scores are strict integers0..100. Returns fixed `from,to,chainId,value='0x0',data,gas` transaction for giveFeedback(agentId,score,0,'starred','csv-reconciliation',origin+'/',uri,hash).
- `verify_feedback(*, buyer, tx_hash, transaction)` returns None pending or verified evidence including feedback_index, is_revoked. Reuse fetch_observations, independently prove exact tx/receipt/common canonical finality and exactly one matching NewFeedback event. Compare complete calldata/tx fields/logs across RPCs, check readFeedback state/index at a verified boundary.
- `registration_transaction()` returns unsigned register(agent_uri) transaction from pinned service owner; it validates code/network but does not require an existing agent ID. No signature, send method or credentials.

## Task 2: Hosted integration and durable feedback

**Files:** `examples/monad_commerce/hosted_feedback.py`, `hosted_service.py`, `hosted_api.py`, `hosted_server.py`; `tests/monad/test_hosted_erc8004.py`; packaging/monad/agentonomy-commerce.service.

**Interfaces:**

- HostedCommerceService gets optional `registry=None` constructor keyword. Provided registry must match scope.network, public_origin and pinned payee.
- `registration_document()` / `public_feedback(hash)` are public metadata methods independent of any browser or tenant runtime. Registration delegates verified registry metadata; unconfigured yields unavailable instead of invented identity.
- `dispatch` adds authenticated `agent_identity`, `feedback_prepare` ({purchase_id,score}), `feedback_verify` ({purchase_id,transaction_hash}), `feedback_status` ({purchase_id}). Preparation/verification require CSRF and current Core owner proof. Execute checks the original preview payment; paid recovery stays original-order only.
- FeedbackStore uses the existing private SQLite database as a dedicated per-wallet/tenant/order feedback record store, separate from ordinary purchase references, with canonical document bytes, keccak hash and per-order uniqueness. Status never generates or broadcasts a transaction. A second score cannot mutate the frozen document; a competing hash cannot overwrite the original submitted candidate. Public documents are available only for independently verified submitted feedback.
- HTTP: GET /agent.json and /.well-known/agent-registration.json, GET /erc8004/feedback/{hash}.json; GET /api/agent; POST /api/purchases/{id}/feedback/prepare {score}; POST .../verify {transaction_hash}; GET .../feedback. Strict schemas, existing Host/Origin/CSRF/error sanitization.
- hosted_server gets `--erc8004-config FILE`, loaded through protected config reader, and constructs RegistryConfig/Client. Public service packaging supplies `/etc/agentonomy-commerce/erc8004.json` explicitly.
