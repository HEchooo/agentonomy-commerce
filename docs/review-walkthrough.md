# 两分钟验收演示

项目主张：**让 Agent 在用户授权预算内，可靠地购买服务并取得结果。**
CSV 收支核对是可验证的付费服务实例；核心展示是授权、预算、付款证据、
交付和幂等恢复之间的闭环。

## 演示前

按 [部署文档](deployment.md) 启动 review API，打开其根地址。只使用页面的
合成示例。展示开始时明确说明：**商家计算经真实 HTTP 完成，结算是沙盒模拟，
不会使用真实资金。** 本地测试不能证明公网部署或真实链上支付。

验收环境只有一份共用预算，初始额度为 1.00 模拟 USDC；每次新订单消耗
0.30。重启不会充值。不要通过删除状态来伪装幂等或预算恢复测试。

## 演示步骤

1. **授权与报价（约 30 秒）**：输入访问令牌，读取预算。载入合成 CSV，
   点击“锁定报价”。此时只冻结输入和价格，预算未扣减，报价有效期 5 分钟。
2. **购买与交付（约 30 秒）**：点击“确认购买”。展示 `delivered`、订单 ID、
   输入/输出摘要与报告。示例三行中有一行重复，实际两笔交易，净额 USD 27.50。
   核对预算已用 0.30、剩余 0.70、结算次数 1、已交付订单 1。
3. **重放与恢复（约 40 秒）**：重放同一笔购买，确认结果及计数不变。
   保存订单 ID，重启同一个服务和同一个持久卷，再查询原订单；结果和预算仍在。
4. **边界与证据（约 20 秒）**：展示 `/health` 和版本声明中的完整提交号，
   对照提交源码。说明错误授权、超预算和不合法 CSV 的拒绝行为；展示自动化
   测试证据，不把 HTTP 200 或付款成功单独当作交付成功。

演示到第三步即可形成一个完整主线。若需要展示超预算，用独立标记的测试状态
执行三笔不同订单，第四笔会进入 `confirmation_required / BUDGET_EXCEEDED`，
不会扣款。不要在主线中重复新建订单来“重试”未知付款结果。

## 已实现与未证明

| 范围 | 本项目的可验证行为 |
| --- | --- |
| Core / Marketplace | 使用迁移的真实授权、策略、预算预占、购买状态机和审计实现 |
| 服务交付 | 实际 loopback HTTP 请求，校验收据范围与输入摘要，执行 CSV 核对 |
| 结算 | 明示的模拟 RPC 和模拟 USDC；未进行真实资金支付 |
| 恢复 | Core、订单、结果和商家幂等记录持久化；重启不补充预算 |
| MCP | 原有 `clink_node` stdio 演示可独立运行；它与本页的 CSV API 不共用状态 |
| 部署 | 提供容器和版本绑定验收脚本；公开 HTTPS 地址仍需实际部署验证 |
| 提交 | 可生成有源码和哈希清单的草稿；不代签权利声明、不声称已获准补交 |

报告保留 7 天，初始签名授权 30 天后到期且不自动续签。当前部署是一个
有访问令牌的共用验收租户，不是多用户生产钱包系统。
